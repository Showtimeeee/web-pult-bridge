# Web Pult Bridge

Приложение на **MicroPython** для **M5Stack Cardputer ADV** (ESP32-S3, экран 240×135,
клавиатура): Cardputer превращается в физический пульт для статических веб-приложений —
**веб-рулетки** и **веб-радио**. По нажатию клавиши устройство шлёт HTTP-запрос на
веб-сервер и показывает состояние на экране.

## Структура

```
web-pult-bridge/
├── main.py            # точка входа: wiring, обработка клавиш, главный цикл
├── config.py          # только данные (клавиши, эндпоинты, пины, таймауты)
├── net.py             # Wi-Fi + HTTP по сокетам (retry, таймауты, JSON)
├── ui.py              # UART-клавиатура + драйвер ST7789 и отрисовка экрана
├── profiles/
│   ├── __init__.py    # реестр профилей, переключение по Tab
│   ├── roulette.py    # профиль веб-рулетки
│   └── radio.py       # профиль веб-радио
├── .env               # секреты (в git не попадает)
├── .env.example       # шаблон секретов (попадает в git)
├── .gitignore
└── README.md
```

## Архитектура

Слоевые модули (`net`, `ui`) не знают про конкретные веб-приложения. Весь
функционал рулетки и радио изолирован в `profiles/` — это единственное место,
которое правится при добавлении нового веб-приложения.

Профиль — модуль с пятью элементами:

| Элемент            | Назначение                                          |
|--------------------|-----------------------------------------------------|
| `NAME`             | имя профиля на экране и ключ в `config.KEYS`         |
| `STATUS_ACTION`    | действие из `config.ACTIONS` для фонового опроса     |
| `HINT`             | подсказка по клавишам внизу экрана                   |
| `apply(data)`      | разбор JSON-ответа сервера в своё `state`, `True` если что-то изменилось |
| `rows()`           | что рисовать в центре экрана: `label` / `value` / `style` / `lines` |

Как добавить новое веб-приложение:

1. В `config.py`: добавить профиль в `PROFILES`, клавиши в `KEYS`, эндпоинты в `ACTIONS`.
2. Создать `profiles/<name>.py` по образцу существующих.
3. Зарегистрировать модуль в `ALL` в `profiles/__init__.py`.

Больше ничего трогать не нужно — Tab, опрос, экран и ошибки подхватят его сами.

Главный цикл (`main.py`): синхронизация Wi-Fi → чтение клавиш → фоновый опрос
статуса (`STATUS_POLL`) → снятие `ERR` через 2 сек → перерисовка при `dirty`.

## Секреты

Реальные значения Wi-Fi и адрес сервера живут в `.env` — файл добавлен в
`.gitignore` и на GitHub не уедет. В репозитории хранится только `.env.example`.

Переменные, которые понимает `main.py`:

| Переменная     | Куда попадает            |
|----------------|--------------------------|
| `WIFI_SSID`    | `config.WIFI["ssid"]`    |
| `WIFI_PASSWORD`| `config.WIFI["password"]`|
| `BASE_URL`     | `config.SERVER["base_url"]` |

При старте значения из `.env` перекрывают то, что лежит в `config.py`
(в `config.py` остаются только заглушки `YOUR_SSID` и т.п.).
Если `.env` не найден — приложение стартует на заглушках и пишет об этом в консоль.

## Управление

Переключение профиля — клавиша **Tab**.

**ROULETTE**

| Клавиша | Действие          | Запрос                            |
|---------|-------------------|-----------------------------------|
| R       | Запустить рулетку | `POST /api/roulette/spin`         |
| S       | Статус            | `GET  /api/roulette/status`       |

**RADIO**

| Клавиша | Действие      | Запрос                                       |
|---------|---------------|----------------------------------------------|
| 1 / 2 / 3 | Станция     | `POST /api/radio/station` тело `{"id": N}`   |
| Space   | Пауза/игра    | `POST /api/radio/toggle`                     |
| N       | Следующий трек| `POST /api/radio/next`                       |

Ожидаемые ответы сервера (JSON):

- Рулетка: `{ "result": "Prize Name", "status": "completed" }`
- Радио: `{ "station": "Jazz FM", "track": "Song", "playing": true }`

> **Допущение:** для фонового опроса используется `GET /api/radio/status` (эндпоинт
> нужно подтвердить на стороне веб-приложения — его нет в исходном ТЗ). Опрос раз в
> `STATUS_POLL` секунд, отключается нулём в `config.py`.

## Экран (три зоны)

- **Верх:** `WEB PULT` + имя профиля (`ROULETTE` / `RADIO`).
- **Центр:** результат рулетки, либо станция / трек / playing.
- **Низ:** `ON <ip>` или `OFFLINE`; справа на 2 секунды — `ERR <код>`.

## Ошибки

- **Нет Wi-Fi** — нижняя строка `OFFLINE`, команды не отправляются, всё пишется в консоль;
  переподключение каждые 10 секунд (в `config.py`).
- **HTTP 4xx/5xx** — на 2 секунды в нижней строке `ERR <код>` (например, `ERR 404`).
- **Середина обмена/таймаут** — `ERR TO`.
- **Сервер недоступен** — одна повторная попытка через 2 секунды, затем `ERR CON`.

## Требования

- Cardputer ADV, прошитый **community-сборкой MicroPython** с модулями:
  - `st7789` (драйвер экрана, формат вызова micropython-lib:
    `ST7789(height, width, spi, cs, dc, rst, rotation)`);
  - стандартный `machine.UART` — клавиатура Cardputer сидит на UART (rx=15, tx=13, 115200).
- Без модуля `st7789` приложение работает в консольном режиме (всё пишется в REPL).

Пины, поворот экрана и UART — в `config.py`, при необходимости правятся там же.

## Установка и запуск

1. Скопируй шаблон и заполни секреты:

   ```bash
   cp .env.example .env
   ```

   В `.env` укажи `WIFI_SSID`, `WIFI_PASSWORD`, `BASE_URL`. Поведение без секретов
   (таймауты, пины, клавиши, эндпоинты) правится в `config.py`.

2. Загрузи файлы на устройство (`.env` тоже — он читается прямо с флеша).
   Обрати внимание: папку `profiles/` тоже нужно залить, включая `__init__.py`:

   ```bash
   mpremote connect auto cp config.py :
   mpremote connect auto cp .env :
   mpremote connect auto cp -r profiles :
   mpremote connect auto cp net.py ui.py main.py :
   mpremote connect auto run main.py
   ```

   либо через Thonny (Target = MicroPython device) — просто перетащи все файлы
   и папку `profiles` в корень файловой системы устройства.

3. В консоли смотри логи: `[env]`, `[wifi]`, `[cmd]`, `[lcd]`, `[key]`.

## Отладка

- **Экран перевёрнутый** → поменяй `DISPLAY.rotation` в `config.py` (0/90/180/270).
- **Клавиши не реагируют** → проверь `KEYBOARD` (uart/rx/tx) и вывод REPL: символы
  должны появляться при нажатии. Спецклавиши с многобайтовыми кодами сопоставляются
  в функции `read_keys()` в `ui.py`.
- **`ERR CON`** → сервер недоступен с Cardputer: проверь IP, что сервер слушает
  `0.0.0.0`, и что устройства в одной сети.
- **Не рисуется картинка** → в логе будет `[lcd] экран недоступен ...` — проверь,
  что сборка прошивки содержит модуль `st7789`.

## Статус проекта

Архитектура переработана относительно исходного ТЗ («всё в одном `main.py`»):
логика разделена на слоевые модули и пакет `profiles/` с изоляцией по фичам.
Дальше — проверка на реальном железе, уточнение эндпоинтов и новые профили
под другие веб-приложения.
